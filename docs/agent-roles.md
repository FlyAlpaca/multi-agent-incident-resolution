# Agent 角色与交接规范

## 角色边界

### 协调者

协调者负责用户交互和工作流状态，不替代独立证据。它必须维护：

- 当前事件输入、仓库根目录和 Git 工作区快照
- `evidence.md`、`diagnosis.md`、`issue-ledger.md` 等运行工件
- 每个 Agent 的模型、推理强度、任务边界和结果
- 修复选择、阶段确认、复发扫描和最终交付状态

### 调查 Agent

调查 Agent 只收集事实：日志窗口、进程/端口、配置、复现、源码路径和测试入口。它可以指出候选问题，但不能把日志警告直接当作根因，也不能修改工作区。

### 诊断 Agent

诊断 Agent 对每个候选问题给出 symptom、trigger、root cause、violated invariant、downstream effect、分类和置信度。它必须说明最小修复、拒绝的替代方案、验收测试和文档影响。

### 实施 Agent

实施 Agent 是唯一写入者。它只能实施用户确认且诊断批准的 issue 集合，保留不相关改动，补充行为测试，并记录实现偏差和尝试次数。新发现的问题必须返回分诊，不得顺手扩大修复范围。

### 验证 Agent

验证 Agent 将验证与实现判断分离，按风险逐步运行 focused test、相关回归、质量检查和有界复发扫描，并检查诊断残留。它不能用无关测试通过替代原始故障验证。

### 独立复核 Agent

独立复核 Agent 必须与实施者独立，读取事件输入、所有工件、规则、最终 diff、源码和测试。它重点检查根因有效性、权限边界、未分诊问题、测试缺口、安全性、公共契约和文档同步。复核结果必须明确 `PASS`、`FAIL` 或 `BLOCKED`。

## 交接最小字段

每次 Agent 交接必须包含：

1. 事件输入和当前工作区根目录
2. 相关 `AGENTS.md` 和 Skill 参考文档
3. 本次运行的绝对工件目录
4. 有界任务、允许读取/写入的范围和服务控制权限
5. 当前阶段、尝试次数、已知风险和停止条件
6. 需要返回的结构化字段和终态标记

禁止将密码、临时令牌、数据库连接串或未经脱敏的 SDK 输出传给 Agent 或写入工件。

## 路由与升级

默认路由是能力下限，不是强制创建 Agent 的数量：

- 调查和验证：`gpt-5.6-luna`，`max`
- 诊断和独立复核：`gpt-5.6-sol`，`medium`
- 实施：`gpt-5.6-luna`，`max`

任何高于角色默认的模型、推理强度或计算配置都必须在派发前单独获得升级确认。保持默认路由时仍需披露 Agent 角色、模型、推理强度和有界任务。
