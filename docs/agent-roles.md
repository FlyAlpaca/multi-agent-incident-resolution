# Agent 角色与交接规范

## 角色边界

- **协调者**：维护用户确认、事件范围、工件、问题台账、路由记录、阶段状态和最终交付；不以协调判断替代独立证据。
- **调查 Agent**：只读收集日志、运行态、配置、复现、源码路径和测试入口；可提出候选问题，不把可疑日志直接视为根因。
- **诊断 Agent**：只读建立症状、触发、根因、违反的不变量、下游影响、分类和置信度，并提出最小修复与验收测试。
- **实施 Agent**：唯一源码写入者；只实施已批准、已选择的问题，保留无关改动并记录尝试次数。新增问题返回分诊。
- **验证 Agent**：只读验证原始故障、focused test、相关回归、质量检查、复发模式和诊断残留。
- **独立复核 Agent**：不参与实施且只读；对最终差异、证据、范围、安全、契约、测试和文档进行对抗性复核，返回 `PASS`、`FAIL` 或 `BLOCKED`。

默认路由以 [SKILL.md](../SKILL.md#coordinate-agents) 为准；它是角色默认值，不是必须创建的 Agent 数量。

角色中的“只读”专指不得修改项目源码；各角色可写入分配给自己的运行工件，验证阶段也可产生仓库规则允许的测试或构建输出。实施 Agent 是唯一可修改项目源码的角色。

## 交接字段

每次交接至少包含：

1. 事件输入、工作区根目录和适用的仓库规则；
2. 本次运行的绝对工件目录；
3. 当前阶段、尝试次数、已知风险和停止条件；
4. 有界任务以及读取、写入和服务控制权限；
5. 所需结果工件、结构化字段、终态集合，以及终态交接后立即结束当前 turn 的义务；
6. 结果导向的 Work Step、专属 `state.md` 路径（复杂或异常任务可附 `events.jsonl`）、初始等待、健康检查节奏和可信下一里程碑。

完整台账字段见 [references/artifacts.md](../references/artifacts.md)。不得在交接或工件中包含密码、令牌、连接串或未经脱敏的敏感输出。

## 运行与回显

每个派发任务的状态字段、Checkpoint、存活判断、干预阈值、生命周期终止例外、终态交接和用户回显以 [子 Agent 状态与超时协议](../references/subagent-state.md) 为唯一权威来源。任务状态与 worker 运行时状态是两个独立门禁：任务活动时协调者只被动观察且不发送后续消息；任务终态后立即回收仍存活的 worker，且不受无进展阈值限制。切换阶段前必须分别确认任务已交接、worker 已退出，并完成结果消费、台账记录和可见回显。

## 路由与升级

路由选定后，为每个实际子 Agent 建立并复用规范标签：

`<角色或稳定标识>（模型：<精确模型>；推理强度：<精确强度>）`

派发前同时说明有界任务；后续进度、替换、终态和最终总结都复用该标签。完整披露门禁和升级确认菜单见 [references/confirmation.md](../references/confirmation.md#subagent-routing-disclosure)。

## 运行工件

Skill 创建的证据、草稿、缓存和进度状态均放入当前 `RUN_ARTIFACT_DIR`。完整或提前正常完成后只清理这个经过校验的运行目录；其他退出状态保留工件。边界和脚本调用见 [references/workflow.md](../references/workflow.md#run-artifact-cleanup)。
